# How we work together (Toivo + Vaishnav)

## Who owns what
| Area | Owner | Files |

Don't edit the other person's files without saying so first. Shared files: append, don't rewrite.

## Git rules
- **Always pull before you start and before you push:** `git pull --rebase`.
- **Small commits, push often** (at least every hour). The commit history is our "progress during the event"
  evidence.
- Work directly on `main`. It's two people with separate folders, so branches aren't worth it.
- If a pull gives a conflict in a shared file: keep both sides, then tell the other person.
- Never commit secrets (API tokens, LUMI/IBM keys) or big files (>10 MB). `data/raw/` is ignored.

## Where things are
- **Numbers for slides:** only from `CLAIMS.md`. Every number there says what produced it (exact /
  Monte Carlo / QAE simulator / Q20 / IBM) and which script. If a number isn't in CLAIMS.md, it doesn't go on a slide.
- **Charts for slides:** `out/*.png` (regenerated by scripts; don't edit by hand).
  - `out/joint_floods.png`: floods come together (observed vs model vs independence)
  - `out/index_price.png`: the index cover price, regulator view vs Tulva vs snow outlook
  - `out/qae_scaling.png`: when does quantum matter?
  - `out/loader_check.png`: all 14 areas on one quantum circuit
- **Demo app:** `web/`. Run `python3 -m http.server 3141 --directory web` and open http://localhost:3141.
  Refresh its data with `python scripts/export_web.py`.
- **Decisions:** `DECISIONS.md`, one line per decision that affects the other person (date · who · what · why).

## Using Claude Code (both of us)
- Open Claude Code in the repo root so it reads `CLAUDE.md` (project context + rules).
- Tell it which folder is yours, so two agents don't edit the same file.
- Agents follow the same rules: pull before push, no prep code from outside this repo, numbers only from code.
